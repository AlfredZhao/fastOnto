# fastOnto：使用 LinkML 快速构建本体的可行性研究 V1.0

以 SH 只读销售数据为例，验证 fastOnto 围绕四个问题形成的最小闭环：

> **如何构建本体、定义什么内容、如何映射数据、如何使用本体。**

核心原则：

- **LinkML YAML** 是本体模型主源；
- **SH** 仍是只读业务数据主源，不复制业务数据；
- **LLM** 仅辅助理解、路由与结果表述，不生成或执行 SQL。

## 1. 如何构建本体

平台以 LinkML YAML 定义本体，通过校验、保存版本和关系图辅助建模。

```text
业务语言 / 数据字典
→ LinkML 类、属性、关系、类型与约束
→ 模型校验
→ 保存模型版本
→ 关系图查看与调整
```

以销售场景为例，核心概念包括：

```text
Customer、Product、Channel、Promotion、Country、SalesRecord
```

- `Customer`、`Product` 等是具有稳定业务标识的实体；
- `SalesRecord` 是销售事实概念；
- 因 `SH.SALES` 没有可靠的永久业务主键，不为销售明细伪造永久 RDF 身份。

> 关系图用于阅读和布局，LinkML YAML 仍是唯一模型主源。

## 2. 本体需要定义什么

本体不是简单给数据库字段改名，而是定义业务对象及其分析语义，主要包括四层：

| 层次 | 内容 | 销售示例 |
|---|---|---|
| 对象 | 类、标识、说明 | 客户、产品、销售记录 |
| 属性 | 数据类型、必填性 | 销售日期、金额、数量、产品类别 |
| 关系 | 对象之间的关联 | 销售记录关联客户、产品、渠道、促销 |
| 分析语义 | 指标、维度、时间与展示规则 | 销售额、销量、月趋势、商品 Top N |

其中，LinkML 主要描述前三层；指标、场景和展示规则由平台治理能力承载。

当前销售分析的受控指标包括：

```text
销售额 = SUM(SH.SALES.AMOUNT_SOLD)
销售数量 = SUM(SH.SALES.QUANTITY_SOLD)
```

可按月份、商品、品类、客户、渠道和促销等维度分析。未定义的指标，例如“利润”，不允许临时猜测或查询。

## 3. 如何映射数据

映射用于建立“本体概念”与“只读业务源字段”之间的明确对应关系，不复制 SH 数据，也不开放用户提交任意 SQL。

| 本体类 | SH 表 | 稳定主体字段 | 典型属性 |
|---|---|---|---|
| Product | `SH.PRODUCTS` | `PROD_ID` | 名称、类别、标价 |
| Customer | `SH.CUSTOMERS` | `CUST_ID` | 姓名、城市、国家 |
| Channel | `SH.CHANNELS` | `CHANNEL_ID` | 渠道名称、类别 |
| Promotion | `SH.PROMOTIONS` | `PROMO_ID` | 活动名称、起止日期 |

销售分析涉及的多表关联由服务端预先审阅和控制，例如：

```text
SALES.PROD_ID     → PRODUCTS.PROD_ID
SALES.CUST_ID     → CUSTOMERS.CUST_ID
SALES.CHANNEL_ID  → CHANNELS.CHANNEL_ID
SALES.PROMO_ID    → PROMOTIONS.PROMO_ID
SALES.TIME_ID     → TIMES.TIME_ID
```

因此，映射的作用是让模型语义与源表字段可追溯对应，而不是让用户自由编写 Join、SQL 或 SPARQL。

## 4. 如何使用本体

本体的价值不止于展示关系图，而是让自然语言问题稳定落到受控的指标分析过程：

```text
自然语言问题
→ 识别本体对象、指标、维度与时间
→ 匹配受控查询模板
→ 返回结果表、图表和追溯信息
```

例如：

- “每月销售额趋势怎样？”：销售额 + 月份维度 + 趋势图；
- “销售额最高的 10 个商品是什么？”：销售额 + 商品维度 + Top N 排名；
- “本月销售额和销量是多少？”：销售额、销量 + 同一时间范围；
- “利润最高的商品是什么？”：拒绝回答，因为当前没有定义利润指标。

LLM 只能协助识别问题意图；最终执行仍由服务端固定模板和已定义指标控制，保证口径稳定、结果可复现、过程可追溯。

## 当前结论与下一步

当前方案已验证以下最小闭环：

```text
LinkML 建模
→ 版本化保存
→ 只读源映射
→ 受控指标分析
→ 自然语言问答与结果追溯
```

下一步需要进一步补齐运行契约：在每次分析结果中明确锁定并展示本体版本、映射版本、指标版本、场景版本和查询模板版本。
