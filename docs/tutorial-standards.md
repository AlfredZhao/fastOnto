# 15 分钟上手：标准与发布机构

## 0. 练习目标与边界

用一个很小的模型认识 **类、实例、数据属性、对象属性、IRI、约束和版本**。

模型文件：`models/standards-tutorial.yaml`。这是借鉴本地 `reference/GBT+48000.3-2026.pdf` 的教学子集，**不是完整标准本体，也不是合规认证示例**。demo 命名空间、属性名和状态枚举仅供教学。它省略了信息单元、结构层次、表达形式、制定程序等标准领域要素。

本练习不读取或修改 SH，不创建业务副本、不新增数据库表、不发布 RDF 映射。点击“保存版本”只会保存平台模型元数据。现在可通过“新建模型”选择教学模板；默认示例仍为销售，不自动导入数据库。

## 1. 先看懂一张图（2 分钟）

```text
模型层：  标准 Standard ──发布机构 issuedBy──> 机构 Organization
             │                                  │
          编号、日期、状态                       名称

实例层：  “教学标准 A” ──发布机构──> “示例标准研究中心”
```

| 概念 | 本例 | 标准阅读位置 |
|---|---|---|
| 实体类型／类 | Standard、Organization，是一类事物的定义 | §3、§5.2、§6 |
| 实例 | 教学标准 A、示例标准研究中心，是具体事物 | §3、§8 |
| 数据属性 | 标准编号是字符串，发布日期是日期 | §7.2 |
| 对象属性 | issuedBy 指向一个机构，不是机构名称字符串 | §7.3 |
| 定义域 Domain | 本例 issuedBy 的使用主体是 Standard；当前模型以类内属性表达其归属 | §7、附录 A.2 |
| 值域 Range | issuedBy 的对象类型为 Organization | §7、附录 A.2 |
| IRI | 类型、属性、实例的明确标识，不是页面显示名称 | §5.4、附录 A |
| 公理／约束 | 如实施日期不得早于发布日期；当前尚不能执行此规则 | §8.2 |

注意：类内属性不等于已经实现完整的全局 `rdfs:domain` 管理。`identifier: true` 也不是数据库唯一索引，更不代表平台已经执行全局唯一性检查。

## 2. 安全地打开教学草稿（2 分钟）

1. 如果当前工作区有未保存内容，先保存原模型，或点击 **YAML** 下载备份。
2. 点击 **新建模型 → 标准与发布机构**，如提示覆盖未保存草稿，确认已完成备份再继续。
3. 确认顶部是 **“独立草稿”**，已保存模型下拉框是 **“当前草稿”**；源码已载入教学模型。
4. 也可选择 **导入文件**，上传 `models/standards-tutorial.yaml`，校验预览后导入独立草稿。

也可在项目目录执行以下只读命令查看模型后复制：

```bash
cat models/standards-tutorial.yaml
```

**新建与保存不同。** 打开已有模型后直接粘贴并点击“保存版本”，仍会给原模型增加修订；仅修改 YAML 的 `name` 不会解除记录关联。应使用“新建模型”“导入文件”建立独立草稿，或用“另存为新模型”保存副本。不再需要刷新页面。

## 3. 校验并观察（3 分钟）

点击 **校验模型**，预期得到：

- “该快照已通过模型结构校验。”
- 左侧 **2 个类**：发布机构、标准。
- 选中“标准”：右侧 **7 个属性**，包括公共的 id、label 和 5 个专有属性。
- 选中“发布机构”：右侧 **2 个属性**，id、label。
- “关系”页签显示 **Standard — 发布机构 → Organization**，共 1 条类间关系。

对照源码观察：

```yaml
issuedBy:
  title: 发布机构
  range: Organization
  required: true
  multivalued: false
```

含义：模型声明标准通过该属性关联机构；该属性必填且为单值。**这是约束声明，不是已检查数据库中每条记录。** 缺少“多值”标签对应这里的单值设置。

`title` 用于显示名称；`description` 用于概念解释。当前检查器并不展示所有元数据，请同时查看源码。

## 4. 保存与导出（2 分钟）

1. 在确认是独立草稿后，点击 **保存版本**。
2. 预期第一次保存显示 **版本 1**；已保存模型列表出现“教学示例：标准与发布机构”。
3. 点击 **YAML** 下载模型源码；点击 **JSON Schema** 下载生成文件。
4. 仅将模型顶部 `title` 改为“教学示例：标准与发布机构（练习版）”。
5. 注意旧检查结果的提示；重新校验，再保存，预期为 **版本 2**。

这里的版本是**模型源文件的修订版本**，不是标准文件的发布年份、替代关系或标准生命周期。页面还可点击 OWL／SHACL 下载 Turtle 文件；生成 SHACL 不代表执行了实例验证。

## 5. 动手做两个实验（3 分钟）

### 实验 A：错误引用

将 `issuedBy` 的 `range: Organization` 改成 `range: MissingOrganization`，点击校验。

预期：报告未知类型。恢复后重新校验。这说明平台会检查**模型中引用的类型是否存在**。

### 实验 B：对象属性和数据属性不是一回事

将同一个 `range` 临时改成 `string`，再校验。

预期：结构校验依然通过，但类间关系由 **1 条变成 0 条**。原来指向机构对象的关系，变成了字符串值。

这说明“语法正确”不代表“业务语义正确”。机构名称字符串不能替代机构的身份及其全部关系。实验结束恢复 `range: Organization`，重新校验；无需保存错误语义版本。

## 6. 认识实例与规则（3 分钟）

以下均为**虚构教学记录**，不是实际标准信息：

| 类型 | 实例 IRI（简写） | 示例值 |
|---|---|---|
| Organization | `https://example.org/fastonto/tutorial/data/org-001` | 名称：示例标准研究中心 |
| Standard | `https://example.org/fastonto/tutorial/data/std-001` | 名称：教学标准 A；编号：DEMO-001；状态：active；发布日期：2026-01-01；实施日期：2026-02-01 |

该标准实例的 issuedBy 应指向上述机构实例 IRI，而不是指向 `demo:Organization` 这个**类的 IRI**。

区分三个层次：

- `demo:Standard`：标准这个类型的标识。
- `demo:issuedBy`：发布机构这个关系的标识。
- `.../data/std-001`：某一份具体标准的标识。

**不要把上述实例表或数据 YAML 粘贴进模型源码区。当前页面没有实例录入、导入或实例校验功能。**

思考三条规则：

1. 实施日期早于发布日期，应该违反日期先后规则（§8.2）。
2. 标准编号重复，应该触发相应的唯一性规则（§8.2）。
3. 状态填 `banana`，应该违反本教学枚举。

当前平台不会检查这些实例。前两项还缺少对应规则的完整建模能力；第三项虽已在模型中声明枚举，也没有实例验证入口。生成 SHACL 文件不等于执行 SHACL 校验。

此外，标准与机构若使用同一个类 IRI，当前校验也未能阻止；不要用此缺口作为有效建模方式。

## 7. 与原来的 SH 业务示例对应

| 教学模型 | 销售业务中的类似概念 |
|---|---|
| Standard 类 | Product 类 |
| 教学标准 A 实例 | 某一件具体产品 |
| standardNumber 字符串属性 | 产品类别等数据属性 |
| Standard → Organization 对象关系 | SalesRecord → Product 对象关系 |
| 发布日期／实施日期的先后规则 | 数量、金额等业务约束（须由业务确认） |

两者共同点是“先定义概念和关系，再把数据映射到这些概念”，而不是把表简单改名成本体。本教学模型没有 SH 映射；保存它不会改变现有客户／产品虚拟 RDF。也不要把示例规则直接当作销售业务规则，例如退货可能产生负数，不能未经确认就要求所有金额非负。

## 8. 推荐的标准阅读顺序与完成检查

阅读顺序：**§3 → §5.2 → 附录 A → §7 → §8 → §6.2、§9**。

先理解模型组成，再理解元数据、关系和规则，最后看标准数字化领域的完整核心类型及扩展方式。附录 A 为规范性附录；附录 B/C/D 为资料性示例，不应把所有示例代码直接当作必须照搬的实现。

完成后应能回答：

- 为什么 Standard 和某份具体标准不是一回事？
- 为什么 issuedBy 应指向机构对象，而不只是一个名字？
- 为什么模型校验通过，仍不能说明业务数据合规？
- 为什么保存模型版本不会修改 SH，也不会自动发布业务映射？

答清这四个问题，就掌握了当前平台最重要的使用边界。
