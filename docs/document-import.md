# 新建本体与文档辅助建模

## 入口

- **新建模型**：选择空白模型骨架、销售示例、标准与发布机构。骨架包含可改名的 Entity，满足至少一个类的要求。
- **导入文件**：选择 LinkML YAML 或业务文档。
- **另存为新模型**：创建新的平台记录、版本从 1 开始，保留原模型；不会自动改变语义 IRI，需要不同本体身份时请修改 id、name 和命名空间。
- **保存版本**：已有模型新增修订；独立草稿首次建立模型。
- **YAML / JSON Schema / OWL / SHACL**：下载当前快照的产物。OWL 和 SHACL 为 Turtle 文件（`.ttl`），导出不等于执行实例校验。

不再需要靠刷新解除旧模型关联。覆盖未保存源码须确认；下拉框“当前草稿”仅表示状态，不是新建命令。

## 文档生成流程

1. 登录并完成首次改密，点击 **导入文件**，选择 XLSX、DOCX、UTF-8 Markdown 或 TXT。
2. 审核候选类、属性、来源位置和局限说明。原工作台内容保持不变。
3. 修改模型技术标识、中文名称、命名空间；增删类和属性。在“类型或目标类”选择另一个类，就建立对象关系。必填与多值默认关闭，须根据业务确认。
4. 勾选审核确认，点击 **生成并打开独立草稿**。服务端生成并校验 LinkML；重复标识或失效类型引用会被拒绝，候选保留供修正。
5. 检查工作台源码和关系，点击 **保存版本**，按需导出。

YAML 上传则先结构校验、预览，再导入独立草稿。修改候选会撤销审核勾选。工作区路由切换保留向导状态；关闭向导须确认，取消请求的旧响应不会覆盖新稿。刷新/退出仍会丢失内存候选，请留意提示。原文件和候选不落盘，只有明确保存的模型元数据持久化。

## 规则与边界

这是**本地有界预处理 + 所选 LLM 候选分析**的辅助建模流程。LLM 输出不等于已确认语义，不保证自动生成完整本体或认证标准符合性；候选必须人工审核。

| 格式 | 提取规则 |
|---|---|
| XLSX | 可见工作表首个非空行作表头，每表一个候选类、每列一个 string 属性；数据行不进入模型。隐藏工作表跳过。 |
| 数据字典表 | 表头同时包含“实体/类/实体名称/class/entity”和“字段/属性/字段名称/字段名/field/attribute”时按实体分组。可选“类型/数据类型/type/range”和“说明/描述/description”。每行实体须填全，不补全合并值。 |
| DOCX | 正文表格走同一规则；未产生表格候选时识别 Heading1–6/标题1–6 样式标题。一般正文、图片、文本框、页眉、附件不做语义推断。 |
| Markdown | 简单管道表格；没有表格候选时识别 ATX 标题（# 至 ######）。代码块忽略。不支持复杂转义、HTML 表格或 Setext 标题。 |
| TXT | 接受 UTF-8 文本；不猜测自然语言语义，提示无候选，允许手工添加类和属性。 |

数据字典识别 string/integer/decimal/float/double/boolean/date/datetime/uriorcurie 及“字符串、整数、小数、布尔、日期”。未知类型暂用 string 并告警；对象关系人工设置。不根据样本猜测必填、基数、唯一性或枚举。

中文名称存为 title。技术标识仅使用 ASCII 字母、数字、下划线且不以数字开头；中文表头生成 Entity1/field1 等占位标识，应审核修改。同名概念跨表不自动合并，可删除冗余候选并补充属性，或在生成的 YAML 中整理。

## 最小数据字典示例

可上传项目中的 `models/document-dictionary-example.md`；也可将下表复制到 Excel 或 Word：

| 实体 | 字段 | 类型 | 说明 |
|---|---|---|---|
| Standard | standardNumber | string | 标准编号 |
| Standard | issuedDate | date | 发布日期 |
| Standard | issuedBy | string | 待确认：是否指向发布机构对象 |
| Organization | name | string | 机构名称 |

审核时将类的中文名称改为“标准/发布机构”，把 issuedBy 的类型改为 Organization。生成后应有两个类、一条对象关系。这是模型定义示例，不是业务记录或完整标准本体。

## 安全与容量

- 单文件最多 2 MiB；仅导入接口接受最多 3 MiB Base64 JSON。其他业务接口仍限 128 KiB，模型 YAML 仍限 64 KiB。
- Office 限标准 UTF-8 XML、非加密 OOXML；最多 256 个包条目、解压总计 12 MiB、单 XML 4 MiB，另限制压缩比、XML 深度/节点数。不是完整 Office 兼容器。
- 不解压到磁盘；拒绝路径穿越、重复包条目、宏、外部工作簿链接和 XML DTD/实体；不执行公式、不使用公式缓存值、不访问外部关系。不渲染上传 HTML。
- 最多 30 个候选类、每类 100 个属性、总计 120 个属性；每表数据字典最多 200 行。超限明确报错，不静默截取部分模型。
- 新接口继承数据库会话、首次改密、Origin 与 CSRF 保护。没有匿名上传或任意代码/SQL/SPARQL 执行。
- 文档会在平台内存中预处理，并发送给所选 HTTPS LLM 生成候选；上传前应确认该 LLM 服务的数据处理协议。平台不保存上传原文件。
- 不修改 SH、不导入业务实例、不创建数据库迁移、不发布 RDF 映射；只有点击保存才写模型元数据。

更新后由用户按现有流程手工重启后端并刷新页面；本次不自动启停常驻服务。
