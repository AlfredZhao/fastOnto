# 本体能力演示指引

完整的四问测试手册见 [`platform-four-questions-test.md`](platform-four-questions-test.md)。

本指引用于演示 fastOnto 当前围绕“构建、定义、映射、使用”形成的基础能力。所有业务数据仍保持在只读源中；本体、映射与规则资产均为可追溯的治理元数据。

## 1. 构建本体

1. 进入“模型工作台”，使用模板、新建或文档导入创建 LinkML 草稿。
2. 点击“校验模型”，查看类、属性和对象关系。
3. 在下方“本体关系图”中拖拽类卡片，演示图形化关系浏览；布局会自动保存到当前浏览器，可点击“恢复默认”。
4. 属性超过四个时，点击“展开其余 N 个属性”查看完整字段列表。
5. 保存版本，或下载 YAML、JSON Schema、OWL、SHACL。

关系图的拖拽只整理阅读布局；LinkML YAML 是唯一模型主源。

## 2. 定义对象、规则、指标和操作

1. 在 LinkML 中定义类、属性、对象关系、数据类型、标识字段和约束。
2. 进入“业务域治理”，新建业务域和本体，并关联一个已保存的 LinkML 模型版本。
3. 点击“定义规则、指标或操作”，以业务语言填写范围、口径/条件和预期结果，保存为声明式草稿。

规则、指标和操作目前用于治理、追溯及后续应用设计；平台不执行用户填写的 SQL、SPARQL、脚本或表达式。

## 3. 映射单表与多来源语义关联

1. 在已关联模型的本体下点击“新建字段映射”。
2. 选择 SH 白名单表，或同一业务域下已登记的外部 Oracle 只读数据源表/视图。
3. 选择本体类、主体标识字段和 IRI 模板；点击“自动匹配字段”生成同名字段建议，并人工确认后保存。
4. 点击“校验模型与数据表”，查看属性匹配、模型缺失字段、未纳入源字段、可用主键和对象关系待审核项。
5. 为同一本体至少建立两个映射草稿后，可创建“跨源实体对齐草稿”，声明两个已映射字段具有 `IDENTITY` 语义。

自动匹配不执行数据库查询之外的操作，只基于已取得的字段元数据给出建议。当前不支持多表 Join、跨源联邦查询、复杂转换或自动实体匹配；实体对齐是治理声明，不会产生 join 或合并业务记录。

## 4. 使用本体：准确性、追溯与应用设计

- **查询准确性**：模型结构经过 LinkML 校验；查询仅使用白名单 SQL 与审阅过的固定虚拟 RDF 模板，不开放任意 SQL/SPARQL。
- **追溯**：本体关联保存的 LinkML 版本；映射、实体对齐、规则、指标和操作均作为独立草稿资产保留。
- **应用设计**：在本体下点击“下载蓝图”，导出当前模型版本和治理资产数量，作为语义检索、经营看板、智能助手或后续业务应用的交接基线。

下载的应用构建蓝图不是运行时应用、映射发布文件或授权凭证。实例级 SHACL 校验、通用查询台、映射发布与自动应用生成仍属于后续阶段。
