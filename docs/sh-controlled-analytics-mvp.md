# SH 受控指标问答 MVP：从零配置与演示

> 目标：以 Oracle 示例业务源 `SH` 跑通“本体 → 映射 → 指标 → 场景 → 受控问答 → 追溯”的最小闭环。平台不复制 SH 行，不允许 LLM 或用户提交 SQL。

## 0. 前提和边界

- 已在 `FASTONTO / ORCLPDB1` 依次执行迁移；本 MVP 新增 `009_controlled_analytics_mvp.sql`。
- SH 是外部、只读业务源。不要修改 SH 表、索引、权限或行。
- 指标结果是查询时刻的实时聚合，不是历史快照；`SH.SALES` 没有永久销售明细身份，因此本手册只做聚合分析。
- 运行模板固定在服务端 `backend/app/analytics.py`；指标配置绝不包含 SQL、SPARQL、脚本或表达式。

## 1. 本体：建立销售分析的语义骨架

1. 登录后打开 **模型工作台**，选择“销售”模板，或载入 `models/sales.yaml`。
2. 校验模型。确认至少包含：`Customer`、`Product`、`Channel`、`Promotion`、`SalesRecord`。
3. 确认 `SalesRecord` 指向客户、产品、渠道、促销的对象属性，以及 `sale_date`、`quantity`、`amount` 属性。
4. 保存为独立模型版本，例如“SH 销售分析本体 v1”。
5. 在关系图中拖动卡片仅调整浏览器内布局；语义主源仍是 LinkML。

本体回答的是“销售额属于什么业务概念、可按什么对象分析”，不是把销售记录复制成图数据。

## 2. 治理：创建业务域与本体记录

1. 打开 **业务域与本体**，创建业务域：名称“销售分析”，标识 `sh_sales`。
2. 在该域创建本体：名称“SH 销售分析本体”，标识 `sh_sales_ontology`。
3. 为本体关联第 1 步保存的 LinkML 版本。

## 3. 映射：只配置已知字段

为以下对象分别创建单表映射草稿。每个主体模板必须使用对应源主键：

| 本体类 | SH 表 | 主体字段 | 建议属性字段 |
|---|---|---|---|
| Product | `SH.PRODUCTS` | `PROD_ID` | `PROD_NAME`、`PROD_CATEGORY`、`PROD_LIST_PRICE` |
| Customer | `SH.CUSTOMERS` | `CUST_ID` | 名称、`COUNTRY_ID` |
| Channel | `SH.CHANNELS` | `CHANNEL_ID` | `CHANNEL_DESC`、`CHANNEL_CLASS` |
| Promotion | `SH.PROMOTIONS` | `PROMO_ID` | `PROMO_NAME`、起止日期 |
| Country | `SH.COUNTRIES` | `COUNTRY_ID` | 名称、区域 |

`SalesRecord` 不要伪造永久 IRI；它用于指标聚合，通过受控模板与上述维度关联。多表关联也不允许填写 Join SQL：已审阅模板只允许以下键关系：

```text
SALES.PROD_ID     → PRODUCTS.PROD_ID
SALES.CUST_ID     → CUSTOMERS.CUST_ID
SALES.CHANNEL_ID  → CHANNELS.CHANNEL_ID
SALES.PROMO_ID    → PROMOTIONS.PROMO_ID
SALES.TIME_ID     → TIMES.TIME_ID
```

## 4. 指标和场景口径

MVP 当前只开放两个原子指标：

| 指标 | 固定口径 | 可分析维度 |
|---|---|---|
| 销售额 `sales_amount` | `SUM(SH.SALES.AMOUNT_SOLD)` | 月份、商品、品类、客户、渠道、促销 |
| 销售数量 `quantity_sold` | `SUM(SH.SALES.QUANTITY_SOLD)` | 月份、商品、品类、客户、渠道、促销 |

预设五个场景：销售总览、销售趋势、商品经营、客户贡献、渠道与促销。

本 MVP 约定 `SH.SALES.AMOUNT_SOLD` 按人民币口径展示；若源数据实际币种不同，必须先经业务确认并建立汇率/换算指标，不能在问答界面临时换算。利润、毛利、成本不属于已发布指标，系统必须拒答。

## 5. 使用：受控问答和追溯

打开 **指标问答**：

1. 先点击“商品经营”中的 `销售额最高的10个商品是什么？`。
2. 页面将问题路由到：指标 `sales_amount`、维度 `product`、年份为空（全量可见期间）、返回条数 `10`。
3. 结果展示数据表及追溯信息：场景、指标口径、模板 `sh_sales_v1`、参数、读取的 SH 表与实时只读边界。
4. 切换到“指标验证器”，选择“销售数量 + 渠道”，验证同一受控模板可按允许维度重用。
5. 输入“利润最高的产品是什么？”；预期系统拒绝执行，并说明尚未定义利润指标。

## 6. 与直接 LLM 问库的对比

| 方式 | 问题“表现最好的商品是什么？” | 结果特性 |
|---|---|---|
| 直接 LLM 问库 | “最好”可能被解释为销售额、销量、利润或增速；模型也可能临时生成不同 SQL | 不稳定、难审计、存在越权/错误口径风险 |
| 本 MVP | 要求命中已定义指标和维度；未定义的利润口径拒答 | 固定模板、绑定参数、可复现、可追溯 |

LLM 在后续版本可以参与意图识别，但输出只能从平台下发的场景、指标、维度和参数枚举中选择；服务端必须重新校验，绝不能执行 LLM 生成的 SQL。


## 7. LLM 与探索模式

配置并启用默认 LLM 后，平台会向 LLM 提供**受限的场景、指标、维度和参数枚举**，让其理解自然语言；服务端会拒绝范围外计划，绝不执行 LLM 返回的 SQL。查询结果最多取 30 条聚合行供 LLM 生成中文解读；不发送凭据、SQL 或明细业务行。

“受限探索”用于尚未沉淀正式指标的问题。它依然只调用审阅过的 SH 聚合模板，并在结果中标识“探索结果，未形成正式业务口径”；不能作为报表或审计结论。

客户名称展示可在 **指标问答 → 客户展示规则** 中配置“姓在前/名在前”和分隔符，保存后对后续客户分析生效。


## 8. 相对时间

“本周、本月、本季度、本年、上周、上月、上季度、上年”按 `Asia/Shanghai`、自然年、周一为周首计算。平台将相对语义归一化为 `[开始日期, 结束日期)` 并写入结果追溯，绝不把无法识别的时间词静默扩大为全部数据。

“本月销售额和销量是多少？”可同时返回两个已发布原子指标；二者必须共享同一归一化时间范围。
